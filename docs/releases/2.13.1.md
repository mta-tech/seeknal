**Status: unreleased.** This patch is based on
[v2.13.0](https://github.com/mta-tech/seeknal/releases/tag/v2.13.0), released

## Changes

- **Prefect image packaging (#112):** copy `docs/cli` into the build context
  before installing Seeknal, satisfying Hatch's existing wheel forced include.
- **Dependency floors (#113):** require pydantic-ai-slim 1.107.4 (with the 1.x
  upper bound), fsspec/s3fs 2026.6.0, aiohttp 3.14.4, multidict 6.9.1, Mako
  1.4.2, and Apprise 1.11.0 in the optional Prefect extra. Core and Ask AI
  declarations share the floor; gateway/worker manifest installs enforce the
  aiohttp floor. The gateway build also copies required CLI docs.
- **Version and documentation (#114):** set `pyproject.toml`,
  `seeknal.__version__`, and the project lock entry to 2.13.1; correct stale
  2.13.0 candidate labels. Dependency lock changes are limited to #113's
  reviewed update and the project version.

## Upgrade considerations

No additional configuration migration is required from 2.13.0. Projects
upgrading from 2.12.1 should follow the [upgrade guide](../cli/upgrade.md).
The [2.13.0 verification and known limits](2.13.0.md#compatibility-and-verification)
remain applicable; this patch does not resolve the recorded macOS ARM native
crash. The blocked native crash reproducer is outside this validation scope.

Apprise 1.11.0 adds redirect controls but still follows redirects by default.
For untrusted notification destinations, explicitly configure `redirect=no`
or `AppriseAsset(http_redirects=False)`; this patch does not change notification
runtime behavior. The bounded public-data workload uses observed Palmer Penguins
rows with synthetic batch-version metadata, a deterministic local model boundary,
and disposable services. It does not establish live-provider quality, production
cloud IAM, Windows compatibility, or throughput.
