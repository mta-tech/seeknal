# 2.14.0 release notes

**Status: unreleased.** This minor release is based on
[v2.13.0](https://github.com/mta-tech/seeknal/releases/tag/v2.13.0), released
on 2026-10-20. It folds in the never-published 2.13.1 work and adds the Ask and
HTTP worker changes from PR #118. No 2.14.0 publication is claimed by this page.

## Ask limits and model settings

- `tool_call_limit` configures the per-turn tool-call budget for read-only Ask
  analysis. Synchronous, streaming, quiet, Prefect, and gateway paths apply the
  same configured limit and degrade to an evidence-synthesis answer when it is
  exhausted. Full toolset mode remains unbounded and logs when the setting is ignored.
- `agent_harness.model_settings` accepts optional `temperature`, `max_tokens`,
  `top_p`, and `seed` values. Invalid or out-of-range YAML values are ignored
  before provider calls; explicit Python settings retain precedence, including
  an explicit empty dictionary.

Both keys are optional. Existing `seeknal_agent.yml` files remain valid and no
configuration migration is required.

## HTTP worker delivery resilience

- Event POSTs carry `X-Seeknal-Event-Id`, and the gateway deduplicates event IDs
  for in-flight work so transport retries do not publish duplicate SSE events.
- Event delivery retries transient failures with bounded backoff. Completion
  delivery has its own time-boxed retry window and carries the full final answer.
- Completion reconciliation reports `dropped_event_count`, `answer_dropped`,
  `done_dropped`, and bounded `undelivered_events`. The reference gateway can
  replay missing interaction events and terminal output on the existing SSE channel.
- Gateway poll failures back off, retain periodic warning visibility, and log
  recovery. Vanished work aborts promptly without leaking the session lock.

The wire additions are optional for compatibility. Upgrade workers and gateways
together to obtain deduplication, persistent completion, and replay behavior.
The [gateway worker protocol](../reference/gateway-worker-protocol.md) defines
field limits and retry/deduplication semantics.

## CI-equivalent Docker test runner

The local Docker test runner mirrors CI's dependency set and default pytest
command in one containerized test phase. Its generated build context excludes
environment files, local virtual environments, agent state, worktrees, and
other local-only artifacts so credentials and machine state are not copied into
the test image.

## Dependency and Docker fixes (formerly 2.13.1)

- **Prefect image packaging (#112):** copy `docs/cli` into the build context
  before installing Seeknal, satisfying Hatch's wheel forced include.
- **Dependency floors (#113):** require pydantic-ai-slim 1.107.4 (with the 1.x
  upper bound), fsspec/s3fs 2026.6.0, aiohttp 3.14.4, multidict 6.9.1, Mako
  1.4.2, and Apprise 1.11.0 in the optional Prefect extra. Core and Ask AI
  declarations share the floor; gateway/worker manifests enforce aiohttp.
- **Version and documentation (#114):** the reviewed dependency and Docker
  changes are incorporated into 2.14.0 rather than publishing 2.13.1.

## Upgrade considerations

Projects upgrading from 2.13.0 need no database, catalog, or project-file
migration. The new Ask keys and HTTP worker fields are additive. Projects on
2.12.1 should also follow the [upgrade guide](../cli/upgrade.md) for the 2.13.0
catalog, backfill, parameter, empty-output, Iceberg, and session-ID changes.

The optional Prefect extra requires Apprise 1.11.0 or newer. Redirects remain
enabled by default; for untrusted notification destinations, explicitly set
`redirect=no` or `AppriseAsset(http_redirects=False)`.

The [2.13.0 known limits](2.13.0.md#known-limits) still apply. In particular,
the recorded macOS ARM large-batch native crash is not resolved by this release.
The historical records above do not establish live provider quality, production
cloud IAM, Windows compatibility, deployment, or throughput.
