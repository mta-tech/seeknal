# 2.13.0 release notes

**Released: 2026-10-20.** [v2.13.0](https://github.com/mta-tech/seeknal/releases/tag/v2.13.0)
was released from [PR #111](https://github.com/mta-tech/seeknal/pull/111),
based on 2.12.1. Verification below records the integration candidate checks.

## Included behavior

- **Conditional Iceberg upsert:** matched rows are accepted only when
  `when_matched_update_if` is true. False and NULL preserve the stored row.
  `compare_columns` declares additional target columns available to the
  predicate. New keys insert by default or are excluded with
  `when_not_matched: skip`.
- **Configuration parity:** conditional options propagate through profiles,
  YAML targets, stackable Python decorators, the typed pipeline
  `MaterializationConfig`, and `IcebergStoreOutput`. Unset typed values inherit
  defaults. YAML target dictionaries can explicitly clear an inherited
  predicate together with `compare_columns: []`.
- **Backfills and parameters:** `--date` anchors date functions, source paths
  are templated, and Python decorator parameters reach `ctx.params`.
  Functional parameter changes also invalidate feature-group and SOA caches.
- **Lakekeeper configuration:** `LAKEKEEPER_URI` is canonical and
  `LAKEKEEPER_URL` remains a fallback alias. If both differ, URI wins.
- **Empty SQL results:** a SELECT returning zero rows replaces the previous
  intermediate parquet with a typed empty file. Downstream nodes receive the
  current empty result; publication errors fail the node.
- **Session paths:** tenant/session identifiers must be valid single path
  segments whose resolved location is strictly below their storage base.
- **Installed CLI documentation:** wheel/sdist packages include CLI topics;
  installed package topics take precedence over a current project's docs.
  Read the new [conditional upsert topic](../cli/iceberg-upsert.md) with
  `seeknal docs iceberg-upsert`.

The release integrates PRs #95, #107, and #110 plus the previously uncommitted
conditional-upsert work. PRs #92, #106, and #109 are excluded: configurable Ask
limits/model sampling, gateway-poll resilience changes, and the WAF guard are
not additions in this release. See the
[component provenance](../evaluations/seeknal-2.13.0-integration.json).

## Upgrade considerations

Read [Upgrading to 2.13.x](../cli/upgrade.md) before upgrading an existing
project. In particular:

- Missing `{{ env:VAR }}` values without defaults now fail DAG construction
  for transform SQL that previously reached DuckDB unresolved.
- Expect a one-time rerun for Python nodes with decorator parameters and
  feature-group/SOA nodes with parameters. Undeclared Python CLI keys do not
  automatically invalidate every node.
- Conditional writes replace complete rows; they do not implement partial
  updates, SCD Type 2, CDC deletes, or deletion of keys absent from the batch.
- On `conflict`, reconcile the concurrent write and start a new invocation so
  the predicate is evaluated again. For `commit_unknown`, inspect the target
  before retrying; automatic generic retries are suppressed for both outcomes.

## Compatibility and verification

The package requires Python 3.11+. The existing dependency floor remains
DuckDB 1.4.4 and PyArrow 18.1; advanced Iceberg writes check for PyIceberg
0.10.0 or newer at runtime even though the general package dependency allows
older PyIceberg. These floors are not a claim that every combination was
tested. `max_batch_bytes` limits the incoming Arrow batch, not all join/writer
memory; conditional reads do not guarantee file or partition pruning.

### Known limits

On macOS ARM, the 2,400-row composite-key case terminates a native process with
SIGILL/SIGBUS during the target-key scan with PyArrow 23.0.0, on both tested
PyIceberg 0.10 and 0.12 environments. Smaller local cases pass; the exact large
case passes on Linux CI. The cause is unresolved: Linux success does not mean
the macOS issue is fixed.

The project type check still reports three pre-existing `SessionStore.list`
annotation errors, also present on main. They are separate from the native
crash. Core Ruff checks introduced no diagnostics over the corresponding main
files. No compatibility or type-check guarantee beyond this evidence is implied.
