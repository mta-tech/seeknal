02

Bagaimana fitur ini dibuat?

Saya membagi pekerjaan menjadi bagian kecil, dibantu agen untuk implementasi dan pemeriksaan terpisah. Setiap keputusan penting diperiksa lewat kode dan pengujian.

Langkah 1 · definisikan

Sepakati arti “mengganti”.

Anda memilih: ganti partisi yang datang dalam batch. Dari situ, kami menetapkan aturan ID, data kosong, dan bagian yang harus tetap utuh.

Keputusan pengguna menjadi dasar implementasi.
Langkah 2 · pisahkan

Buat ruang kerja sendiri.

Branch baru dibuat langsung dari main. Pengembangan berlangsung di cabang itu, sehingga main dan file lokal Anda tetap terjaga.

Seperti mengerjakan salinan sebelum mengubah buku utama.
Langkah 3 · buktikan

Coba mesinnya lebih dulu.

Kami mencoba penulisan pada tempat uji lokal. Setelah data ditulis, pembaca lain membacanya kembali untuk memastikan hasil benar.

PyIceberg menulis; DuckDB memeriksa hasil.
Langkah 4 · rangkai

Hubungkan semua pintu.

Pengaturan YAML, kode Python, dan feature store diarahkan ke penulis yang sama untuk dua mode baru. Aturannya tetap konsisten.

Tim mengerjakan konfigurasi, penulis, dan tes secara terpisah.
Langkah 5 · tantang

Sengaja buat situasi sulit.

ID bermasalah, pengaturan salah, dua penulis bersamaan, hingga balasan server hilang. Kami mencari keadaan yang bisa membuat data salah.

Kesalahan yang ditemukan diperbaiki, lalu diuji ulang.
Langkah 6 · periksa

Minta pemeriksaan terpisah.

Reviewer kode dan reviewer arsitektur memeriksa hasil. Setelah perbaikan, pengujian dijalankan lagi dan paket aplikasi dibangun.

Hasil akhir: review disetujui, build berhasil.

Catatan teknis & sumber angka

Penjelasan ini merangkum pekerjaan pada commit 77328f7, di branch feat/iceberg-upsert-insert-overwrite. Branch dibuat dari main 269fc20. Main dan empat file lokal yang dipantau tetap utuh. Status ini adalah snapshot pekerjaan, bukan pembacaan repository secara langsung.

Angka 402 berasal dari regresi 18 suite: 402 passed, 4 skipped. Putaran QA setelah review: 77 passed. Reviewer kode dan arsitektur merupakan pemeriksa yang terpisah dari implementasi. Saat validator ID sengaja dinonaktifkan pada proses uji terisolasi, tes terkait benar-benar gagal; setelah dipulihkan, hasil kembali lulus.

Implementasi memakai PyIceberg 0.10.0 yang tersedia, tanpa mengubah lockfile dependency. Mode upsert memerlukan unique_keys; insert_overwrite memerlukan partition_by yang cocok dengan partisi identity. Versi awal tidak mencakup SCD Type 2, CDC delete, transform partisi, atau evolusi partisi.

Input kosong tidak menghapus partisi. Jika target belum ada: create_table: true menjadi no-op; create_table: false gagal. Batas batch default 256 MiB mengukur ukuran logis Arrow, bukan batas memori proses. Transaksi berlaku per tabel target, bukan serentak untuk semua target.

Lint/typecheck pada core baru lulus; pemeriksaan modul legacy secara menyeluruh masih memiliki temuan baseline. Kegagalan write dapat meninggalkan file staging yang tidak direferensikan; pembersihannya memerlukan prosedur retensi yang aman, terutama saat hasil commit tidak pasti.
